# 3.2 Search Engine: TF-IDF Cosine and BM25

We implemented a review-level inverted index and two ranking functions from scratch: TF-IDF with cosine similarity and Okapi BM25. The shared tokenizer is applied at both indexing and query time, while SQLite provides persistence rather than ranking. The official experiment uses the deterministic 50,000-review sample because a full-corpus index is not required by the assignment. Six diverse queries show materially different rankings under the two models; these differences are interpreted through overlap, document length, lexical coverage, and qualitative review inspection rather than treated as relevance accuracy.

## 3.2.1 Architecture and Index Construction

The search component reads each prepared review's stable `doc_id`, original text, and display metadata through the shared reviewer interface. The shared tokenizer lowercases text, preserves contractions and emoji, splits hyphenated words, removes punctuation from the indexed representation, retains stop words such as `and`, `the`, and `not`, and disables part-of-speech filtering. The index stores one posting for each `(term, document)` pair together with within-document term frequency. It also stores review metadata, document lengths, full TF-IDF vector norms, term document frequencies and IDFs, and versioned index metadata.

For document \(d\), term \(t\), and indexed collection \(D\),

\[
|d|=\sum_t f_{t,d}, \qquad
\operatorname{avgdl}=\frac{\sum_{d\in D}|d|}{N}.
\]

All collection statistics are computed from the documents actually included in the index. A valid review with no retained terms still contributes to \(N\) with length zero. The core counting step is:

```python
counts = Counter(_terms(tokenizer, review["text"]))
length = sum(counts.values())
connection.executemany(
    "INSERT INTO postings(term, doc_id, tf) VALUES (?, ?, ?)",
    ((term, review["doc_id"], tf) for term, tf in sorted(counts.items())),
)
document_count += 1
total_terms += length
```

The builder streams reviews and stores intermediate state on disk, so it does not materialize the corpus or posting collection in memory. It builds a temporary database and publishes it only after successful completion. Duplicate document IDs are errors, existing indexes are not overwritten, and loaded indexes are read-only. Each index also stores a tokenizer fingerprint; loading or querying with an incompatible tokenizer policy is rejected.

The official sample uses the original single-process SQLite builder. An optional MapReduce builder can parallelize document parsing and posting construction when `[index].workers` is explicitly set between 2 and 8. It publishes the same schema and does not change the loader or either ranking formula. A separate compact backend stores integer postings and NumPy vectors, but neither optional backend changes the reported default experiment.

## 3.2.2 Ranking Models

### TF-IDF cosine similarity

The implementation uses logarithmic term frequency and smoothed inverse document frequency:

\[
\operatorname{idf}_T(t)=\ln\frac{N+1}{df_t+1}+1,
\]

\[
w(t,x)=(1+\ln f_{t,x})\operatorname{idf}_T(t),
\]

\[
s_T(q,d)=\frac{\sum_{t\in q\cap d}w(t,q)w(t,d)}
{\lVert\mathbf{w}_q\rVert_2\lVert\mathbf{w}_d\rVert_2}.
\]

The document norm contains all indexed terms in the document, including terms absent from the query. Query weights use the same index-local IDF. Out-of-vocabulary query terms are removed before computing the query norm so that an unknown term cannot dilute the contribution of known terms.

### Okapi BM25

The implementation uses a positive-IDF BM25 variant:

\[
\operatorname{idf}_B(t)=\ln\left(1+\frac{N-df_t+0.5}{df_t+0.5}\right),
\]

\[
s_B(q,d)=\sum_{t\in q\cap d} f_{t,q}\operatorname{idf}_B(t)
\frac{f_{t,d}(k_1+1)}
{f_{t,d}+k_1(1-b+b|d|/\operatorname{avgdl})}.
\]

The baseline uses \(k_1=1.5\) and \(b=0.75\). Repeated query terms contribute linearly through \(f_{t,q}\); no separate query-frequency saturation parameter is introduced. Average document length is the global index statistic, not the average of the current matching documents.

For both models, candidates are the union of postings for the known query terms, giving OR matching. Results are sorted by decreasing score and then increasing `doc_id` for deterministic ties. Empty, punctuation-only, and all-OOV queries return no matches. The index does not store token positions, so it provides no phrase, proximity, or highlighting semantics.

## 3.2.3 Experimental Design

The deterministic bottom-\(k\) sample was selected with seed 42 and FNV-1a priorities after scanning all 6,990,280 reviews and joining 150,346 business records. It contains reviews dated from 19 April 2005 through 19 January 2022. The experiment uses the six queries embedded in `[analysis.search].queries` in `configs/sample.toml`:

1. `good service`
2. `cheap Italian restaurant`
3. `family friendly atmosphere`
4. `slow delivery`
5. `best coffee and breakfast`
6. `not worth the price`

These cover service, price and cuisine, ambience, delivery, meal preferences, and a negated value judgment. Both models use identical documents, preprocessing, queries, and \(K=10\). Every query term occurs in the sample index. The queries are exploratory information needs rather than a representative benchmark, and no relevance labels were constructed.

| Collection statistic | Value |
|---|---:|
| Indexed reviews \(N\) | 50,000 |
| Indexed vocabulary | 56,040 |
| Retained term occurrences | 5,247,734 |
| Global `avgdl` | 104.95468 |
| Distinct businesses | 29,390 |
| Prepared input size | 43.32 MiB |
| Current SQLite index size | 233.59 MiB |

For each query we record Top-10 set overlap and Jaccard agreement, mean returned-document length, and the fraction of returned documents containing all distinct filtered query terms. The final measure is lexical coverage, not precision: a review can contain all words while failing the intended meaning. Query timings use one untimed warm-up followed by the configured timed repetitions in the same process; they are observations of one environment rather than a controlled performance benchmark.

## 3.2.4 Results and Discussion

All six queries returned ten results under both models, but their first-ranked documents were different. Top-10 overlap ranged from two reviews for `best coffee and breakfast` to six for `family friendly atmosphere`. BM25 returned longer reviews and achieved higher all-query-term lexical coverage for every query in this sample.

| Query | Top-10 overlap | TF-IDF mean length | BM25 mean length | TF-IDF coverage | BM25 coverage |
|---|---:|---:|---:|---:|---:|
| good service | 3 | 14.8 | 20.6 | 0.90 | 1.00 |
| cheap Italian restaurant | 3 | 25.7 | 77.8 | 0.10 | 0.40 |
| family friendly atmosphere | 6 | 23.5 | 31.6 | 0.60 | 1.00 |
| slow delivery | 4 | 22.8 | 65.7 | 0.10 | 0.60 |
| best coffee and breakfast | 2 | 24.0 | 62.9 | 0.10 | 0.80 |
| not worth the price | 4 | 19.1 | 34.0 | 0.40 | 1.00 |

The differences do not automatically indicate that one model failed. For `good service`, TF-IDF first retrieved an eight-token First Watch review that directly praised breakfast food and service. BM25 first retrieved a 30-token Asian-market review that repeatedly praised service, freshness, and prices. Both are plausible lexical answers, although their lengths and domains differ. For `family friendly atmosphere`, both first results discuss the intended concept, but the models prioritize different reviews.

OR matching explains several weaker cases. For `cheap Italian restaurant`, TF-IDF's first result concerns a Mexican restaurant and matches `cheap` without satisfying the cuisine requirement. BM25's first result describes an inexpensive meal at an Italian chain, yet lower-ranked results can still use `cheap` in phrases such as *cheap tasting* or *not cheap*. Similarly, a review can match `friendly` and `atmosphere` without mentioning families.

Word sense and negation remain unresolved. For `slow delivery`, some retrieved reviews praise fast delivery or use *delivery* for the arrival of dishes during a meal. For `not worth the price`, BM25's first result contains the explicit negative value judgment, whereas TF-IDF first retrieves a positive discussion of price and value without `not`. Both models still retrieve a directly relevant criticism second. These are limitations of lexical matching rather than arithmetic errors.

Coverage can also understate useful content. For `best coffee and breakfast`, BM25's first result endorses both concepts but lacks the literal stop word `and`; requiring all query terms therefore marks it incomplete. This is why higher lexical coverage cannot be relabeled as precision or used to claim that BM25 is universally better.

### BM25 parameter sensitivity

We varied one parameter at a time around \((k_1,b)=(1.5,0.75)\): \(b\in\{0,0.75,1\}\) at \(k_1=1.5\), and \(k_1\in\{0.5,1.5,2\}\) at \(b=0.75\). Removing length normalization by setting \(b=0\) produced the largest change.

| Query | Baseline mean length | Mean length at \(b=0\) | Baseline Top-10 retained |
|---|---:|---:|---:|
| good service | 20.6 | 479.9 | 0 |
| cheap Italian restaurant | 77.8 | 291.5 | 3 |
| family friendly atmosphere | 31.6 | 218.1 | 3 |
| slow delivery | 65.7 | 351.3 | 2 |
| best coffee and breakfast | 62.9 | 391.5 | 1 |
| not worth the price | 34.0 | 238.8 | 1 |

At \(b=0.75\), changing \(k_1\) from 0.5 to 2 preserved the first-ranked review for every query, although some lower ranks changed. These observations show that global length normalization materially affects document selection in this sample. They do not identify an optimal parameter setting; choosing parameters for relevance would require judged development queries and a separate evaluation set.

## 3.2.5 Validation, Limitations, and Reproduction

The integrated suite contains 118 tests, including 102 search-specific tests. Search tests independently verify hand-counted postings, TF-IDF and BM25 scores, complete document norms, repeated and OOV terms, deterministic ties, empty inputs, failure cleanup, persistence, fingerprint mismatch, CLI output, the compact backend, and a small real-interface smoke run. These tests establish arithmetic and integration behavior but do not replace relevance evaluation.

The main limitations are the 50,000-review sample, six exploratory queries, OR matching, absent term positions, no stemming or synonym expansion, and no model of negation scope or word sense. Without consistently judged relevance labels, the report does not claim Precision, Recall, MAP, or nDCG. No full-corpus performance conclusion follows from the sample.

From the project root, the current reproducible workflow is:

```powershell
python -m yelptext prepare --config configs/full.toml
python -m yelptext sample --config configs/full.toml --size 50000 --seed 42
python scripts/run_search_experiment.py --config configs/sample.toml
```

The driver builds or provenance-checks `artifacts/indexes/sample/index.sqlite3`, reads the six queries from `configs/sample.toml`, and writes the manifest, complete rankings, comparison table, and BM25 sensitivity table under `artifacts/search_engine/sample/`. Notebook 04 is presentation-only: it reads these artifacts and lets the reader inspect a selected query rather than rebuilding the index or rerunning the experiment.
